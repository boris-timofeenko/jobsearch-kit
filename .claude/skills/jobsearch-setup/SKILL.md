# Настройка jobsearch под человека

Код общий и уже работает; всё про человека — в папке `my/` (не в git) и в `.env`. Твоя работа — не переписывать
код, а собрать хороший профиль, проверить его на реальных заголовках и вакансиях и довести до первых карточек в
Telegram. Справочник всех полей — `docs/CONFIG.md`, ручная инструкция для человека — `docs/SETUP.md`, устройство и
накопленные решения — `AGENTS.md` (читай, прежде чем трогать логику в `jobsearch/`).

Общайся на языке человека (по умолчанию русский), коротко, по шагам. После каждого шага — команда проверки и её
вывод, а не «должно работать».

## 0. Где ты запущен

- **Claude Code в папке репозитория** (есть терминал) — делаешь всё сам: команды, файлы, проверки.
- **Claude без терминала** (claude.ai, приложение) — не можешь ничего запустить. Тогда: интервью и разбор резюме
  как ниже, на выходе — готовое содержимое `my/profile.yaml` и `my/config.yaml` целиком (одним блоком каждое), плюс
  список команд из `docs/SETUP.md`, которые человек выполнит сам. Схема и пресеты — в `references/` рядом с этим
  файлом, если репозитория не видно.

## 1. Окружение (Claude Code)

```bash
python3 --version                      # нужен 3.9+
python3 -m venv .venv && .venv/bin/pip install -q -r requirements.txt
.venv/bin/python -m pytest -q tests    # должно быть «N passed»
```

Если `my/profile.yaml` уже есть — это перенастройка: прочитай его и `python -m jobsearch check --fast`, спроси, что
не нравится, и переходи к нужному шагу (рецепты — раздел 8).

## 2. Интервью

Попроси резюме: файл (PDF/DOCX/TEX/MD) или текст. Это главный источник: из него сам вытащи роль, уровень, годы,
стек, домены, языки, достижения. Не выдумывай: в `candidate.summary` только то, что есть в резюме, и прямо допиши,
чего НЕТ из типичного для роли (языки программирования, фреймворки) — модель по этому отличает «другой стек».

Затем спроси одним сообщением только то, чего в резюме нет и что меняет поведение (пронумеруй, предложи дефолты):
1. **Где искать.** Основная страна переезда (одна) и дополнительные; или только remote без переезда. Коды стран —
   `presets/countries.yaml` (nl, de, be, fr, es, pt, ie, at, pl, cz, se, dk, fi, it, lu).
2. **Виза.** Гражданство ЕС/ЕЭЗ есть? (`needs_visa: false` выключает всё про спонсорство). Где живёт сейчас
   (`based_in`). Для Нидерландов — год рождения: до 30 лет порог HSM ниже.
3. **Деньги.** Желаемый месячный гросс; минимум, если виза не нужна.
4. **Что точно не надо.** Индустрии, типы ролей, аутсорс/аутстафф, контракт/B2B, уровень.
5. **Сильные стороны**, за которые хочется платить больше (1–3 темы) — станут `focus` и `strengths`.
6. **AI в работе** важен? (бонусы `ai_first/ai_product/ai_tooling` в `fit_adjustments`, по умолчанию 0).
7. **Воронка:** куда уже откликался, где отказали — `known_companies`.
8. **Компании мечты** — для своих досок.
9. **Запуск:** ноутбук (Mac/Linux) или свой VPS; оценка моделью по подписке Claude или API-ключ.

## 3. Профиль

```bash
.venv/bin/python -m jobsearch init --role <qa|backend|frontend|mobile|devops|data|product>
```

Возьми ближайший пресет и перепиши `my/profile.yaml` под человека:

- `candidate`: summary (5–10 строк, факты из резюме + «X, Y в резюме нет»), languages (рабочие, включая родной),
  seniority (junior|mid|senior|lead — по годам и обязанностям, а не по желанию), needs_visa, based_in,
  citizenship_note, birth_year (если цель — Нидерланды).
- `role`:
  - `name`, `definition`, `not_this_role` — текст для модели, самый сильный рычаг качества. `not_this_role` —
    соседние роли и ложные друзья заголовков (для QA: железо, производство, ручное тестирование; для data:
    data entry, финансовый аналитик).
  - `strengths` из ответа 5, `small_gap` — что для этой роли «мелкий пробел» (другой фреймворк того же языка…).
  - `queries` — 6–12 названий вакансий, **самые широкие первыми** (доп. страны и remote ищутся по первым четырём);
    `keywords` — 3–6 коротких слов для сайтов крупных компаний; `categories` — категории досок (см. пресет).
  - `title_include` / `title_exclude` — регэкспы заголовков. Не сужай include до стека: «Software Engineer» —
    нормальный заголовок, стек проверит модель по тексту. Exclude — соседние роли.
  - `stack` — 8–12 тем из резюме с весами 1–3 (`relocation|visa sponsorship…: 6` оставь), `title_boost` — слова
    ядра роли, `focus` — 1–3 сильные темы (regex, score 6–8, fit 1–2), `penalties`, `off_domain` — по пресету.
- `target`: `country` (код), `countries`, `remote`, `salary_target_month`, `remote_base`, `goal_note` (абзац о
  приоритетах человека его словами), `fit_adjustments`. Пороги зарплат в каталоге — ориентиры: если есть веб-поиск,
  сверь порог основной страны с официальным сайтом (IND, Make it in Germany…) и при расхождении переопредели
  `country: {code: de, salary_floor_month: …}`.
- `known_companies`, `exclude_companies`, `agency_companies` — по ответам; списки из примера оставь.

Проверь:
```bash
.venv/bin/python -m jobsearch check --fast
.venv/bin/python -m jobsearch check --title "<10–15 реальных заголовков: подходящие и соседние>"
```
Заголовки для проверки придумай сам из типичных объявлений этой роли в этих странах (включая местные варианты,
например немецкие «Entwickler (m/w/d)»), покажи человеку таблицу ✅/❌ и поправь регэкспы, пока она не станет
правильной.

## 4. Источники

`my/config.yaml` (создан `init`, все варианты в комментариях):
- `company_files`: `my/companies.yaml` и `boards/curated.yaml` всегда; `boards/nl-ind-sponsors.yaml`, если среди
  стран есть Нидерланды; `boards/de-large.yaml` — если Германия.
- Компании мечты: `.venv/bin/python -m jobsearch discover "Company A" "Company B"` печатает готовые строки — добавь в
  `my/companies.yaml`. Не нашлась — у компании своя платформа найма; это нормально, её вакансии придут с LinkedIn.
- `aggregators`: по умолчанию хороши; добавь `iamexpat, undutchables` для Нидерландов, `arbeitsagentur` для Германии.
- Своя страна вне каталога или массовый перебор работодателей страны — `AGENTS.md`, «Массовые списки досок».

## 5. Telegram и модель

Telegram (человек делает руками, ты подсказываешь и проверяешь):
1. В Telegram: @BotFather → `/newbot` → имя → получить токен вида `123456:ABC…` → `TELEGRAM_BOT_TOKEN` в `.env`.
2. Написать своему боту любое сообщение, затем узнать chat id:
   ```bash
   curl -s "https://api.telegram.org/bot$TOKEN/getUpdates" | python3 -c "import json,sys; print({u['message']['chat']['id'] for u in json.load(sys.stdin)['result'] if 'message' in u})"
   ```
   → `TELEGRAM_CHAT_ID` в `.env`. Бот отвечает только этому чату.
3. `.venv/bin/python -m jobsearch telegram-test` — должно прийти «jobsearch на связи».

Модель: на компьютере с залогиненным `claude` ничего не нужно (бэкенд cli). Для сервера — `claude setup-token` на
компьютере человека, токен `sk-ant-oat01-…` (108 символов) человек копирует **руками** в `CLAUDE_CODE_OAUTH_TOKEN`:
при захвате из вывода терминала токен портится. Либо `ANTHROPIC_API_KEY`. Секреты не проси вставлять в чат — пусть
человек сам впишет их в `.env`. `.venv/bin/python -m jobsearch check` показывает выбранный бэкенд.

## 6. Первый прогон и калибровка

```bash
.venv/bin/python -m jobsearch run --time-filter r259200          # 3 дня; 15–40 минут
.venv/bin/python -m jobsearch report --hours 72                  # data/reports/latest.html
.venv/bin/python -m jobsearch list --all --hours 72 --limit 300  # всё, включая отсеянное, с причинами
```
Запускай в фоне и смотри лог. Потом вместе с человеком: открой отчёт, пройди топ-10 (это то, что надо?) и отсеянное
(`list --all`: нет ли среди skip нужного). Правь профиль по причинам отсева (раздел 8), затем
`.venv/bin/python -m jobsearch reanalyze` — пересчитывает эвристики по всей базе, оценки модели сохраняются.
Карточки в Telegram: `telegram-test --sample 3`.

## 7. Расписание

- **Mac**: проект не в `~/Documents`, `~/Desktop`, `~/Downloads` (launchd туда не пускает, расписание молча падает):
  `mv` в `~/jobsearch`, пересоздать `.venv`, затем `scripts/install_launchd.sh 9 13 18 --bot`.
- **Linux-ноутбук**: cron, пример в `docs/SETUP.md`.
- **VPS** (Hetzner/Contabo/любой Ubuntu 22.04+, 2 ГБ RAM хватает): SSH-ключ на root, затем
  `deploy/deploy.sh root@<ip>` — копирует проект, ставит пакеты, venv, Claude CLI (если в `.env` подписочный токен),
  systemd-таймеры (каждые 2 часа 08–22 + ночной deep) и бота. Базу с ноутбука переносить, если первые прогоны были
  локально, иначе первый серверный прогон пришлёт всё заново: `scp data/jobs.db root@<ip>:/opt/jobsearch/data/` и
  `chown jobsearch:jobsearch`. Обновление: `git pull && deploy/deploy.sh root@<ip>`.

## 8. Рецепты настройки

| симптом | что делать |
|---|---|
| нужная вакансия не пришла | `list --all --hours 48` → найти её; нет в базе — заголовок не прошёл `title_include` или источник её не видит; есть со skip — читать причину |
| много мусора с другой ролью | дописать соседние роли в `title_exclude` и `not_this_role` |
| отсекает «текст на немецком» | добавить язык в `candidate.languages`, если человек им владеет |
| «нужен другой язык» на nice-to-have | это ошибка правила — смотри `filters.other_language_required`, `SOFTENERS` |
| fit занижен у хороших | уточнить `summary` (стек, домены), `strengths`, `small_gap`; посмотреть `note` модели в отчёте |
| хорошие в другой стране теряются | добавить страну в `countries` или поднять её в `location_penalty` |
| зарплата режет | порог `salary_floor_month` страны; без визы — поставить свой минимум |
| мало вакансий | больше `queries`, свои доски (`discover`), агрегаторы страны; первые дни — норма, база копится |
| дорого по подписке/API | `llm.min_score_remote` выше, `max_per_run` ниже, `telegram.min_fit` не влияет на стоимость |

После любой правки профиля: `check --fast`, затем `reanalyze`.

## Нельзя

- Коммитить `my/`, `.env`, `data/` (они в `.gitignore`) и вставлять секреты в чат или в логи.
- Запускать два `run` одновременно: одна SQLite. На сервере это держит flock, локально — следи сам.
- Убирать `stdin=DEVNULL` и `--system-prompt`/`--tools ""` у CLI-бэкенда (`llm.py`): без них вызов стоит в 40 раз дороже.
- Подключать Indeed/Glassdoor/StepStone/XING: антибот или запрет в robots.txt.
- Пугаться 429 от LinkedIn: волны по 1–3 дня бывают, следующий прогон догоняет пропущенное сам.
